# Native metadata and development indexing checkpoint

The main layout renders bpm-meta-tags with explicit native page context. Titles preserve native SEO title, escaped tags, pagination only after page 1 and shop name without duplication. Canonical and sharing URLs are escaped. Descriptions come only from nonblank page_description; no source marketing claims or invented fallback description are added. Open Graph type uses request.page_type. Twitter summary/large-image cards share the same native title, description and page_image.

Shopify page_image already selects resource imagery or the store social sharing fallback: https://shopify.dev/docs/api/liquid/objects/page_image . No competing theme image picker was introduced. Protocol-relative image URLs acquire https once; absolute URLs retain their scheme; root-relative URLs resolve against shop.url. Available native alt text is escaped. Native image contents/selection remain a development-theme QA gate; the local bergamot fixture receives an audited image URL whose filename is Unscented_2.png. A filename alone does not prove a wrong image, but inspect native sharing imagery and product attribution before release.

The candidate explicitly sets development_noindex true in settings_data and defaults true in settings_schema. Missing flag also stays noindex. Development storefront pages emit noindex,follow. Only an explicitly false release setting permits normal public pages to omit the robots directive. Cart, search and 404 remain noindex,follow. Customer account routes, captcha and private utility routes stay noindex,nofollow and omit description/social metadata even with release indexing enabled. Dedicated gift-card/password utility layout retains its existing private head. This is an indexing request, not authentication or access protection, and applies only when this candidate renders; it does not change the published theme, store robots.txt, search console or native record visibility.
