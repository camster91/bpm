# Product gallery image loading checkpoint

The Sites homepage hero already uses position-aware eager/high priority versus lazy/auto, native merchant-image responsive widths/sizes and explicit fallback dimensions. The source fallback JPEG is approximately 192 KiB. No hero artwork, crop, responsive layout or image bytes changed in this checkpoint.

A product gallery defect remained: the source override was always eager even when an explicit native variant's featured image was initially selected. That left two eager requests. The purchase section now derives override loading/priority from override_initial. The selected source or merchant override receives eager/high priority; otherwise the unused override is lazy/auto. Native image serialization receives high priority only when the existing gallery selection logic marks it eager. All noninitial native images remain lazy/auto. Existing native responsive widths/sizes are retained, and video preload remains none. Selection, variant forms, native media, thumbnails and all source asset bytes/crop provenance are unchanged.

Shopify's primary performance documentation recommends fetchpriority=high for the LCP image and position-aware loading: https://shopify.dev/docs/storefronts/themes/best-practices/performance/set-fetchpriority-high-on-lcp-image and https://shopify.dev/docs/storefronts/themes/best-practices/performance/use-section-index . These changes are request hints; this checkpoint does not prove which image is actual LCP or measure a speed/transfer improvement.
