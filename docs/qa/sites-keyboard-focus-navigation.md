# Keyboard focus and short mobile navigation checkpoint

Before this change, the local homepage's mobile menu at 375×360 extended from y=86 to y=403 with overflow visible and no internal scroll area. Existing controls used a single teal focus outline, including controls on teal artwork/sections. W3C describes two-color focus indicators as a sufficient technique for visible contrast: https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html . This checkpoint is scoped evidence, not full WCAG conformance.

The base stylesheet now supplies a fixed ink outline with an inner cream ring to retain visibility across brand backgrounds. The shadow wins over hover elevation only while focused. Conflicting Sites focus overrides were removed; forced-color mode uses the system Highlight outline and suppresses the ring shadow. No resting typography, artwork, palette or spacing was changed by these focus rules. Native app iframe styling remains the app's responsibility and is unverified.

The mobile navigation is a block scroll region capped by the dynamic viewport minus actual header and announcement height. Block layout preserves bottom padding; retaining inherited flex layout initially clipped the final link's ring and was corrected during browser inspection. Header height is measured initially, on resize, editor section lifecycle and after fonts settle using the existing bounded chrome binder. Native details/summary semantics and Escape focus return are preserved. The disclosure does not trap focus or become a modal. Local preview asset URLs now include hashes for CSS/JS, avoiding stale cached assets after regenerating fixtures; Shopify's native asset_url behavior is unchanged.

Chrome keyboard proof at 375×360: Enter opens summary; sequential Tab reaches Contact; navigation scrollTop=43, content scrollHeight=316 and clientHeight=273; Contact occupies y=276–331 inside navigation y=84.5–358.5 with both ring colors visible. Escape closes the disclosure and returns focus to SUMMARY. Screenshot sites-mobile-menu-keyboard-local.png records the visible final item. At 820×1000 the header height updates to 108px and document scroll/client widths are both 820. At 1440×1000 both widths are 1440; a keyboard-focused footer link has the ink outline and cream ring on the dark footer.

Temporary CDP reduced-motion emulation produced prefers-reduced-motion true, html scroll-behavior auto, hero-star animation none and track link transition duration 0s. Emulation and viewport override were reset. This does not test active scroll-entry animation suppression because source entry classes are currently not activated by theme JavaScript. That is a newly identified source-motion fidelity gap and must be restored from reference-site with preference handling and progressive visibility. Forced-color rendering, screen-reader behavior, 200/400% zoom, native app widgets, longer merchant menus and physical touch/device QA remain open.

277 existing local rendering checks, gift-card checks, 96 resource bindings, artwork verification and nine app bindings pass. Browser interaction is the affected CSS/navigation evidence; no implementation-mirroring CSS unit checks were added. Shopify Theme Check remains zero errors with the existing Adobe font warning. Full accessibility, performance, source motion fidelity, analytics/consent, claims and critical native journeys are not yet accepted.
